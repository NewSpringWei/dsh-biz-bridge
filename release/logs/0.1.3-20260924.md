# 0.1.3 DSH 0.1.7 适配（alpha.2 → rc.1）

跟随上游升级，并把几处既有隐患一并修掉。**无新增能力、HTTP API 与配置项均无变化。**

> 本版覆盖上游 `0.1.7-alpha.2` 与 `0.1.7-rc.1` 两个预发布步长：alpha.2 那轮做了完整接口核对与代码改动；
> rc.1 复核后未发现接口面差异，只更新依赖与构建配置的版本钉点。

## 依赖与构建配置

*   **6 个 DSH peer**：`^0.1.5-rc.2` → `^0.1.7-rc.1`（`dsh-agent` / `dsh-session` / `dsh-llm` / `dsh-session-persistence` / `dsh-host-webserver` / `dsh-attachment`）。
    区间必须显式升：`^0.1.5-rc.2` 展开为 `>=0.1.5-rc.2 <0.2.0-0`，而带 prerelease 的 `0.1.7-*`
    只在 `[major,minor,patch]` 元组相同时才被该范围接受（`0.1.5` ≠ `0.1.7`），即**旧区间不接受它**。
    `^0.1.7-rc.1` 同时覆盖同 patch 位的后续预发布与 `0.1.7` 正式版。
*   **`pnpm-workspace.yaml`**：`minimumReleaseAgeExclude` 14 项 → `@0.1.7-rc.1`。
    不改会让新版本被 pnpm 的"最小发布年龄"检查拦下。
*   **便携包构建器**：`tools/bundle/bundle.config.json` 的 `dshVersion` → `0.1.7-rc.1`。

## 上游变更对本插件的影响

**DSH 插件服务面无破坏性变更。** 10 个注入/按需探测的服务名全部未变；`agents`、`sessionPersistence`、
`webServer`、`llm`、`sessionQuery`、`attachments`、`systemPrompt`、`tools`、`sandboxPolicy`
的方法签名逐项比对一致；订阅的 `session/event`、`agent/inbox/claimed`、`agent/error` 载荷兼容
（`agent/error` 只多出 `turn`/`step`）。

会话日志从 **v3 走到 v4**（上游 `SESSION_FORMAT_VERSION = 4`）：tool 结果升为一等 tool-role 消息、
消息 `source` 改为生产者自带、`turn/end.reason` 新增 `forked`。插件解码所依赖的字段
（`assistant/message`、`assistant/attempt`、`turn/end`、`user/message`）**一个都没动**，
`src/dsh/decode.ts` 这一层因此零改动。

**唯一会打到业务侧的变化**：官方 `llm-deepseek` 的默认模型目录由 4 项收缩为 2 项 ——
`deepseek-v4-flash` 与 `deepseek-v4-flash-vision-exp` 已被移除，现只剩 `deepseek-flash` 与 `deepseek-v4-pro`。
业务方若显式传 `params.model: "deepseek-v4-flash"` 会失败；**图片入站现在只有 `deepseek-flash` 可选**
（目录中唯一带 `image` 的多模态模型）。

## 修复与清理

*   **`security.denyTools` 改为逐名生效**：DSH 的 `tools.restrict()` 对整批名字先校验、后应用 ——
    名单里只要有一个当前作用域不存在的工具名，整批就抛错、**全部限制都不生效**。改为逐名调用后，
    未知名字只淘汰它自己。此前配 `denyTools: ['bash','web']` 而宿主只注册了 `web` 时，`web` 也会被漏掉。
*   **去掉 `user/message` 双形状兜底**：DSH 0.1.5 起该事件的 `data` 就是 `UserMessage` 本身，
    探测 `{ message }` 包装的那一半永不命中，已删（含同步调整的单测用例）。
*   **死代码**：移除 `runner.ts` 的 `TERMINAL_END_KINDS` / `isTerminalEndKind()`（无调用点）
    与只写不读的 `started` 字段。
*   **文档**：`docs/api.md` 的模型示例改用现存模型；源码与测试注释里的"0.1.5 / v3"更新为"0.1.7 / v4"。

## 兼容性

*   HTTP API、请求/响应字段、配置项**均无变化**，业务方无需改动 —— 除非显式写死了已移除的模型 ID。
*   插件只与**同版本宿主**运行：不承诺旧版 DSH 宿主兼容，也不为 0.1.5 期落盘的旧会话数据保留读取分支。
    升级宿主前若需保留旧会话，先在宿主侧执行 DSH 的 `migrate:sessions-to-v4`（未迁移的 v3 会话在
    会话消息查询接口上会表现为 500，而不是 404）。
*   `cordis` / `schemastery` 的 peer 区间不变：上游的 4.0.4 / 3.18.4 仍被 `^4.0.2` / `^3.18.2` 覆盖。
