## 一、问题与根因

**现象**：同一个 `session_id` 的后续请求改 `params.provider` / `params.model` 被**静默忽略** ——
任务照常成功，只是仍走该会话第一次用的那个模型；只有换 `session_id` 才换得动。
下游（jsxmsp 填表助手 PoC）据此把"换模型"实现成"换会话"，代价是丢掉切换点之前的对话上下文。

**根因不在 DSH，在本插件的下发方式**：模型此前只经 `AgentOptions` 下发，而它是 **agent 实例级**的
—— 只在 `ctx.agents.create/resume` 那一刻进 DSH，之后由实例持有。而 `AgentPool.openAgent`
的决策流路径 a（live 复用）**直接返回 live agent，把本轮 `agentOptions` 丢掉**；桥接进程常驻、
又从不主动销毁 live agent（§5.2.2），于是同一会话后续的覆盖永远进不去，且**全程无报错**。

**DSH 本身支持会话内换模型**，这正是 GUI 走的路。`@deepseek-ai/dsh-agent` 的
`installModelSelection(agentCtx, ref)` 注册三条 scoped listener：

| 事件 | 作用 |
|---|---|
| `system-prompt/assemble` | 每步把当前选择快照进 `ref.assembled`，并写提示词变量 `provider`/`model` |
| `agent/request` | 用快照覆盖请求配置的 `provider`/`model`，并清掉继承的 reasoning effort |
| `agent/pre-step` | 路由变化时往会话追加一条**持久**通告 `[model changed: … the session continues with …]` |

GUI 的 `selectModel`（`@Remote`）同样**复用 live agent、不重建会话**，走的就是这条通道。
`agent-loop` 强注入 `systemPrompt`，且 `preStep` 每步都调 `systemPrompt.assemble`，
所以 headless 的桥接 profile 也必然派发这条瀑布。

## 二、修复

| 文件 | 改动 |
|---|---|
| `src/core/session-bridge.ts` | `SessionGateway` 新增 `applyModelSelection(agent, sessionId, selection)`；`openAgent` 的**四条**返回路径（live 复用 / resume / create / already-exists 回退）统一走一个 `applied()` 收尾 —— live 复用这条正是丢覆盖的地方 |
| `src/dsh/gateway.ts` | 用 `installModelSelection(raw.ctx, ref)` 装载会话级选择；按 `sessionId` 持有 `ModelSelectionRef`（跨请求延续）；`RAW_AGENT` 私有通道作幂等键（`liveAgent()` 每次都重新包装同一个真实 agent，包装对象当不了键） |
| `src/core/model-selection.ts`（新增） | 零 DSH 依赖的纯函数：`sameModelSelection` / `modelSwitchLog` / `modelSelectionInstallLog` |
| `src/index.ts` | 把日志出口接到 `fileLogger` 的 `model-selection` 通道 |
| `tests/model-selection.test.ts`（新增） | 5 项：三字段全等、`undefined` 语义、未变不记、首次/切换文案、装载文案 |
| `tests/session-bridge.test.ts` | +4 项：live 复用也应用选择（回归）、resume/create、回退只应用一次、不带模型时仍传递 |
| `docs/api.md` | `params` 语义更新：`provider`/`model` 为**会话级**选择，同会话改字段下一次请求即生效、上下文保留；省略时**沿用该会话上次的显式选择**，从未指定过才落宿主默认 |

三条实现约束：

*   **只写 `ref.current`**，不碰 DSH 任何内部状态，也不自己拼提示词 —— 通告由 DSH 追加；
    只在 `provider` 与 `model` **成对**给出时更新（单给一个 DSH 会报 `agent has no provider/model`），
    不成对时保持上次选择（会话级选择本就该跨请求延续）。
*   **幂等**：同一个真实 agent 只装一次 listener（重复装会注册多份 `agent/request`，模型被叠加覆盖）。
    listener 挂在 agent 自己的作用域上，agent 销毁时随之释放，桥接不持有 disposer。
*   `params.reasoningEffort` 随同一条通道生效；`maxTokens` 仍是实例级（见 §七）。

## 三、日志

新增文件日志通道 `model-selection`，**变了才记**（每轮都写会把真正的切换埋掉；只换
`reasoningEffort` 也算切换）。判定与文案是纯函数，网关只负责转交。实测输出：

```text
[INFO] [model-selection] 模型选择：会话 biz-system-a:stream:e2e-switch-mv7sjeoj 首次指定 xiaomi/mimo-v2.6-flash（会话级，下一步请求生效）
[INFO] [model-selection] 模型选择：会话 biz-system-a:stream:e2e-switch-mv7sjeoj 的会话级选择已装载到 agent → xiaomi/mimo-v2.6-flash
[INFO] [model-selection] 模型选择：会话 biz-system-a:stream:e2e-switch-mv7sjeoj 由 xiaomi/mimo-v2.6-flash 切到 deepseek-official/deepseek-flash（会话级，下一步请求生效；对话上下文保留）
[INFO] [model-selection] 模型选择：会话 biz-system-a:stream:e2e-switch-mv7sjeoj 由 deepseek-official/deepseek-flash 切到 xiaomi/mimo-v2.6-flash（会话级，下一步请求生效；对话上下文保留）
```

4 行对应 3 次请求（首次指定 + 装载 + 两次真切换），**无重复刷屏**。

## 四、验证

*   **单元测试 176 项**：`pnpm test` → 174 通过。本机受限沙箱下 2 项失败
    （`artifacts` 的符号链接、`db` 的临时目录 `mkdir`，均报 `EPERM`），**与本次改动无关**，
    属环境权限问题而非代码问题。
*   **变异验证**：把 `openAgent` 路径 a 改回 `return live`（即恢复丢覆盖的行为），
    `session-bridge.test.ts` 立即 2 项红；改回即全绿。
*   **端到端（真机、`0.2.0-rc.2` 宿主 + 便携包）**：同一 `session_id` 连发三次，
    会话日志（`runtime/sessions/**/session.v4.jsonl.zstd`，逐帧解码）里 `request/header` 依次为

    ```text
    request #1 → xiaomi / mimo-v2.6-flash          [request/header]
      · 通告 [model changed: … xiaomi/mimo-v2.6-flash; the session continues with deepseek-official/deepseek-flash]
    request #2 → deepseek-official / deepseek-flash [request/header]
      · 通告 [model changed: … deepseek-official/deepseek-flash; the session continues with xiaomi/mimo-v2.6-flash]
    request #3 → xiaomi / mimo-v2.6-flash          [request/header]
    ```

    即：同会话内逐轮按 `params` 路由，DSH 自动追加两条持久通告。
*   **三方同源校验**：`release/dsh-biz-bridge-0.1.4.tgz` 内的 `package/lib/index.mjs`、
    `code/lib/index.mjs`、便携包 profile 里已安装的 `lib/index.mjs` 三者 sha256 相同
    （`9e44ad1d…b699b7b`）。

> 判据说明：本次曾一度打算用"第二次换 `deepseek` 会 402 欠费失败"当判据 —— **该判据已失效**
> （2026-10-14 实测全新会话直连 `deepseek-flash` 返回 200，该账户已可用）。权威判据是
> 会话日志里的 `request/header`，它直接说明实际路由到了哪个模型。

## 五、兼容性

    由 DSH 自己在 GUI 路径写入；本插件只装 listener）。

    `src/config`、`src/shared`、`src/core`、`tests`，**不含 `src/dsh/`**；本机也没有
    `@deepseek-ai/dsh-llm` / `@deepseek-ai/cordis` 的类型依赖。本次对 `gateway.ts` 的类型
    是逐条对照上游同款用法核实的（`installModelSelection(agent.ctx, ref)` 与

    `commands.ts` 一致），并有端到端行为佐证，但**建议把 `src/dsh/` 纳入 include**。
*   **`maxTokens` 仍是实例级**：live 复用时不生效，与本次改动前一致，未纳入本轮范围。
*   **私有设计文档不在仓库内**：`plugins/dsh-biz-bridge/docs/dsh-biz-bridge-design.md` 的
    §5.2.3（会话级模型选择）位于 `code/` 之外，不受本仓库版本控制，需另行留存。
*   本机受限沙箱下 `pnpm test` 的两项 `EPERM` 失败（见 §四）建议在正常开发环境复核一次。
