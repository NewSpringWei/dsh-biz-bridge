# 0.1.2 附件双向转接 + 安全强化

新增能力，纯文本调用方无需改动。

## 变更

**入站（业务系统 → agent）**：`stream` / `callback` 新增可选 `attachments: [{ type, uri, name?, mime? }]`，提交时拉取落盘，执行期转为 DSH 图片/文件内容块随 prompt 投递。

**出站（agent → 业务系统）**：任务执行前后对比工作目录快照，新增/变化的文件登记为产物，清单随 `stream` done 帧、`callback` 投递体、任务详情返回。

**附件下载**：`POST /bizbridge/api/v1/attachments/download`（推荐，签名与其他 POST 接口一致）和 `GET /bizbridge/api/v1/attachments/{id}` 两种方式，验签 + client 归属校验。

**outbound 完整性**：注册时计算内容 SHA256 存入 `task_attachments.content_hash`，下载时校验；业务系统可通过清单的 `content_hash` 字段自行校验。

**账本**：新增 `task_attachments` 表（`CREATE TABLE IF NOT EXISTS` 幂等；缺列时自动 `ALTER TABLE` 补列，存量库可直接升级）。

**配置**：新增 `attachments` 节（开关、条数/字节/总字节上限、拉取超时、host 白名单、出站上限与排除目录），见 `docs/config.md`。

**静态页**：`client.html` 支持附件双向测试（含「填入本机示例」零外部依赖自测）。

## 安全强化

> **前提**：插件面向**可信业务系统**（持私钥、经签名认证的合作方）。通道可信，但业务方转发的
> 内容可能源自更上游，故内容层仍按不可信处理。以下防护的定位是防误用、防跨租户串用、防插件
> 被当跳板，以及可信方被攻破时的纵深——**不是**对不可信调用方的完整防护。

**SSRF 防护**：入站附件 URI 与 `callback_url` 默认拒绝内网/环回/链路本地地址（`denyInternalHosts` 默认 true）。判定在 **IP 字节层**完成，覆盖 IPv4 私有段、IPv6 ULA/链路本地/多播、**IPv4 映射（`::ffff:7f00:1`）/ NAT64 / 6to4** 等映射写法。重定向链手动跟踪（默认最多 5 跳），每跳都重新校验目标 host。

**出站敏感文件排除**：默认排除列表扩展（`.ssh`/`.aws`/`.kube`/`.gnupg`/`.docker`），新增 `sensitivePatterns` glob 匹配（默认排除 `.env*`/`*.pem`/`*.key`/`*.p12`/`*.pfx`/`*.jks`/`*.keystore`/`*.shadow`）。

**内容注入防护**：用户消息前**恒定**附加安全上下文标记（此前仅在带附件时注入），声明消息由可信合作方转发、其内容可能源自上游，故按不可信数据处理，并约束不得执行命令、越界读写、泄露凭据或做破坏性操作。此外把同一约束写入 agent 的**系统提示词段落**（`security.policySection`，默认开启），在桥接会话自己的作用域内生效。

**agent 工具限制**：新增 `security.denyTools`（默认空 = 不限制），通过 DSH 的 `tools.restrict({ deny })` 在桥接会话作用域内真正移除指定工具能力。

**会话沙箱模式**：新增 `security.sandboxMode`（默认 `default` = 不改动部署设定）。设为 `read-only` 时，DSH 在可信代码里**拒绝一切写入与删除**（bash 与文件系统都遵守），模型即使被说服也没有能力执行——这是插件能做的最强结构性约束。按会话持久化，重启按重放恢复；与 `attachments.outbound.enabled=true` 冲突时启动告警。

> **能力边界（如实记录）**：DSH 的**读**操作在所有沙箱模式下都不受边界限制
> （`fs-sandbox`："Reads pass through untouched: every mode permits reading"），
> 因此本插件**无法**把"读"限制在本 client 工作空间内——越界读取需由宿主侧的容器/挂载
> 隔离解决，或直接 `denyTools` 掉读工具。

**错误信息脱敏**：失败结局的 `message` 与 `reason` 中的内部会话 ID（`<clientId>:<stream|cb>:<外部 id>`）替换为 `<session>`。

**安全事件审计**：agent 安全策略的注册/限制结果写入插件文件日志（module=`security`），不再只进 console。

**修复潜在激活失败**：过期清理分支在 `fileLogger` 声明之前引用它（清理计数非 0 时会抛 `ReferenceError` 中断激活），现已把日志器创建提前。

**附件失败回收**：入站附件登记失败时回收已落盘目录，避免账本无记录的孤儿文件。

## 兼容性

- 不带 `attachments` → 行为与 0.1.1 完全一致
- 可选 peer `@deepseek-ai/dsh-attachment`：宿主未挂载时带附件的请求返回 501，纯文本不受影响
- 所有安全防护默认开启，无需改动现有配置
- **`callback_url` 指向内网将被拒绝**：若业务方回调地址确为内网（如内网联调、内网部署），
  需显式设置 `attachments.allowInternalCallbackHosts=true`——它只放开回调地址，
  附件 URI 的内网拦截不受影响（`denyInternalHosts` 仍生效）

## 验证

单测 **149/149 通过**（0.1.1 为 81 项；含 `tests/security.test.ts` 25 项，直接以攻防演练载荷为用例）。

对运行实例（本版构建产物 + 默认配置）的 **56 项端口级验证全部通过**：

- **认证/签名**：无签名、时间戳超窗、nonce 重放、伪造 client、篡改 body 全部 401
- **SSRF**：17 类内网地址（含 `::ffff:7f00:1`／`::ffff:127.0.0.1`／NAT64 `64:ff9b::`／6to4 `2002::`／云元数据／`.local`／`.internal`／整数与短写法）全部 400 拦截；`file:`／`ftp:`／`data:`／`javascript:`／`gopher:` 协议全部拒绝
- **`callback_url`**：内网/映射/元数据/私网地址全部 400 拦截
- **请求面**：方法限制、未知路由、下载路径穿越（3 种编码）、附件条数超限、字段类型校验
- **越权**：跨 client 任务详情 403、跨 client 附件下载 403、任务列表仅见自身（admin 可见全部）
- **其它**：`content_hash` 列存在；失败路径确已发生且未泄露内部会话 ID；安全策略事件落入文件日志；`stream` 端到端 `done` 且回复内容正确拼接
